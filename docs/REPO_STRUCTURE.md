# Repository Structure

This is the BTP-II project repo for "Audio Fingerprinting for Indian Music" (DTU CSE, AY 2025-26). Below is what each folder contains and which files matter.

## Top-level docs

| File | Purpose |
|---|---|
| `BTP_PLAN.md` | 8-chapter project plan — context, model choice, modifications, timeline, decisions to lock |
| `MONDAY_DEMO.md` | Comprehensive 11-section demo doc — slides outline + Q&A prep |
| `LATEST_RESULTS.md` | 1-pager TLDR for live demo — headline numbers + 3 findings |
| `professor.md` | Professor's directive (Hinglish notes from advisor meeting) |
| `README.md` | Entry-point pointer to the docs above |

## `dataset/` — Custom Indian music dataset (gitignored audio files)

21 Hindi/Bollywood songs, 273 test queries total. Per-song layout:

```
dataset/<Song_Name>/
├── original.mp3                 # database entry
├── remix/
│   ├── remix_001.mp3            # full-length remix (1 query)
│   └── clips_a/clip_001.mp3...  # 12 short clips (12 queries)
```

**Audio files are gitignored.** Only `dataset/dataset-metadata.json` is committed (Kaggle dataset metadata). The actual songs are uploaded as a private Kaggle dataset: `aryanbanwala97/audio-fp-indian-music-btp`.

## `scripts/` — Uniform evaluation pipeline

Wrappers that benchmark each fingerprinting library against the same dataset under the same protocol.

| File | Purpose |
|---|---|
| `common.py` | Shared `discover_songs()` + result aggregation schema |
| `compare.py` | 4-way comparison runner — prints accuracy table |
| `dejavu_test.{sh,py}` | Dejavu wrapper (Docker → MySQL DB → fingerprint+match) |
| `olaf_test.{sh,py}` | Olaf wrapper (C binary, lightweight) |
| `panako_test.{sh,py}` | Panako wrapper (Java + Gradle) |
| `results/<lib>_dataset_results.json` | Canonical accuracy result per library |
| `results/trend/` | NeuralFP per-checkpoint results (epochs 2/4/6/8/9/10) |

### `scripts/results/` schema

Every result JSON follows this format:

```json
{
  "library": "dejavu" | "olaf" | "panako" | "neuralfp",
  "data_dir": "dataset",
  "summary": {
    "test_full":  {"total": 21,  "pass": 7, "accuracy": "33.3%", ...},
    "test_clips": {"total": 252, "pass": 77, "accuracy": "30.6%", ...},
    "overall":    {"total": 273, "pass": 84, "accuracy": "30.8%"}
  },
  "per_song": { "<Song_Name>": {"total_pass": 13, "total_tests": 13, ...} },
  "tests": { "test_full": [...], "test_clips": [...] }
}
```

### `scripts/results/trend/` — NeuralFP per-checkpoint trend

Generated by `kaggle_notebook/inference_trend.py` (v4). All 6 checkpoints from a 10-epoch FMA training run, evaluated via **manual checkpoint restore** (576 vars assigned per ckpt, verified unique DB embedding signatures).

```
trend/
├── neuralfp_dataset_results_ckpt-{2,4,6,8,9,10}.json   # full per-query records per ckpt
├── trend_summary.csv     # accuracy table 0/1/2/4/6/8/9/10 epochs
└── trend_plot.png        # U-shape visualisation
```

See `docs/RESULTS_INTERPRETATION.md` for what these numbers mean.

## `kaggle_notebook/` — Kaggle kernel source

Code that runs on Kaggle GPU (P100, 30hr/week free tier).

| File / Dir | Purpose |
|---|---|
| `full_pipeline.py` | Train NeuralFP on FMA + run inference on Indian dataset (training kernel) |
| `inference_trend.py` | Multi-checkpoint inference (no training) — produces trend results |
| `smoke_test.{py,ipynb}` | First validation kernel (env setup + dataset detection) |
| `kernel-metadata.json` | Top-level kernel metadata for the smoke-test kernel |
| `pipeline/` | Push staging dir for `full_pipeline.py` (has its own `kernel-metadata.json`) |
| `trend/` | Push staging dir for `inference_trend.py` (uses `kernel_sources` to attach training kernel's checkpoints) |

The `*.ipynb` files inside `pipeline/` and `trend/` are **generated** from the `.py` source via cell-marker conversion (look for `# %%` markers). Don't edit the `.ipynb` directly.

`kaggle_notebook/runs/` is gitignored — local logs from prior Kaggle runs.
