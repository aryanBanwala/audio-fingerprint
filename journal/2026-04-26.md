### Bug saga (4 kernel versions)

**v1 trend kernel (24.5% identical for all 6 ckpts):**
- Reused single `tf.train.Checkpoint(model=m_fp)` object across loop iterations
- Hit https://github.com/tensorflow/tensorflow/issues/25081 — restore silently no-ops on subsequent calls with same Checkpoint object
- Resulted in all 6 checkpoints producing identical 24.5% (essentially first restore's state)

**v2 trend kernel (RuntimeError on ckpt-2):**
- "Fixed" by rebuilding model + calling `tf.keras.backend.clear_session()` per iter
- New bug: per https://github.com/tensorflow/tensorflow/issues/27937, `clear_session` breaks subsequent restore on rebuilt model
- Diagnostic also broken: looked at `m_fp.trainable_variables` (empty because `get_fingerprinter(cfg, trainable=False)`) instead of `m_fp.variables`
- Manual fallback iterated `trainable_variables` (also empty) → assigned 0 variables → "Manual restore ALSO failed" exception

**v3 trend kernel (5/6 ckpts correct, ckpt-2 partial):**
- Build model ONCE outside loop (NeuralFP's own pattern in `model/generate.py`)
- Fresh `tf.train.Checkpoint` per iteration (not reused — fixes #25081)
- No `clear_session` (fixes #27937)
- Diagnostic uses `.variables` (576 entries) not `.trainable_variables`
- Framework restore logged: `assert_existing_objects_matched failed: Found 64 Python objects unmatched` for every ckpt
- ckpts 4-10: triggered manual_restore fallback when post-restore weights == previous ckpt's weights → got correct values
- ckpt-2: manual_restore did NOT trigger (no `prev_snap` for first iter) → only framework partial restore happened → 24.9% slightly off

**v4 trend kernel (all 6 airtight):**
- Force manual_restore for ALL ckpts (skip framework path entirely)
- Manual restore reads checkpoint via `tf.train.load_checkpoint(path)`, builds shape+name-fragment scoring, assigns each model variable explicitly
- Result: "Manual assign: 576 ok, 0 skipped, 0 ckpt keys unused" for every ckpt
- DB embedding signatures: 6/6 unique → restore confirmed working

### Lesson
`tf.train.Checkpoint.restore(path).expect_partial()` is unreliable for in-process inference. Two failure modes:
1. Reused Checkpoint object → silent no-op (#25081)
2. Even fresh Checkpoint object can leave variables unmatched (~64/576 in our case) — manifests as accuracy drop without any error

For multi-checkpoint evaluation, use direct `tf.train.load_checkpoint(path).get_tensor(key)` + manual variable assignment by shape+name match.
